# Interior tileset — catalog and assembly guide

Files: `public/assets/game/tilesets/interior.png` (16×16 tiles, 16 columns),
`interior.tsj` (Tiled tileset with per-tile properties and animations),
`interior.catalog.json` (names → tile ids; what map authors use).

Rebuild everything (tileset + previews): `python3 tools/art/tiles_interior/build.py`.
Furniture is generated art (prompts in `tools/art/tiles_interior/gen_prompts.py`,
sources cached in `tools/art/gen/raw/int_*.png`, never regenerated by the build),
reduced to tile scale and snapped to `tools/art/palette.py`. Floors, walls, rims,
rugs, mats, counters, stairs, the whiteboard and the inner door are drawn in code.
Demo rooms that use only catalog names: `tools/art/tiles_interior/rooms_demo.py`
(previews in `tools/art/tiles_interior/preview/`).

## Catalog shape

```
tiles:     { name: id }                       single tiles (floors, mats, counters, …)
walls:     { theme: { u, l, u_left, l_left, u_right, l_right,
                      rim_l, rim_r, rim_b, rim_bl, rim_br, rim_tl, rim_tr,
                      void, rim_door_gap } }
stamps:    { name: { w, h, place, base_layer, layers: { base: [[id]], over?: [[id]] }, note? } }
autotiles: { rug_<colour>: {nw,n,ne,w,c,e,sw,s,se},
             counter_<kind>: {l,m,r,s, l_top,m_top,r_top,s_top, (m_top_register)} }
```
`-1` = leave the cell empty. Stamp `base` goes in the layer named by
`base_layer` (`detail` for furniture, `ground` for stairs); `over` goes in `over`.
Properties are on the tiles themselves (see `.tsj`), so a cell is blocked if
any layer holds a `solid` tile.

## Room shell (every room)

Rooms are a rectangle `W × H` cells including a one-cell rim. Wall themes:
`home`, `bedroom`, `neighbor`, `lab`, `center` (teal), `mart` (violet).

```
row 0      rim_tl  u_left  u  u  u … u  u_right  rim_tr      ← wall face, upper (solid)
row 1      rim_l   l_left  l  l  l … l  l_right  rim_r       ← wall face, lower (solid, baseboard)
row 2      rim_l   floor_*_shadow  …               rim_r     ← first floor row: use the _shadow floor
rows 3..   rim_l   floor_* / floor_*_alt …         rim_r
row H-1    rim_bl  rim_b … rim_door_gap … rim_b    rim_br    ← front rim; gap under the exit mat
```
- All of that is the `ground` layer. Columns 0 and W-1 are rims (solid, mostly
  void), so a room with 10 walkable columns is 12 cells wide.
- `u_left/l_left` and `u_right/l_right` are the wall face cells next to the
  side walls (inner-corner shading); use plain `u`/`l` elsewhere.
- Floors: `floor_wood_a` (light planks, home), `floor_wood_b` (dark planks,
  neighbour), `floor_lab` (white/aqua checker), `floor_center`
  (+ `floor_center_inlay` teal diamond for a path to the counter,
  `floor_center_teal` solid teal), `floor_mart` (lilac diamonds). Wood floors
  have `_alt` variants; scatter roughly 50/50 to hide repetition. Every floor
  has a `_shadow` version for row 2 (shadow cast by the wall).
- Exit: put `mat_exit_<green|red|teal|violet>` (`_l`/`_r` for a 2-wide mat) on
  the bottom floor row (`detail` layer; tile has `door: true`) and the warp
  object on it; put `rim_door_gap` (solid void) in the rim cell below it.
- `void` = solid filler for anything outside the room.

## Placement kinds (`place` in the catalog)

- `wall` — goes against the back wall: its **top row sits on wall row 1** and
  its bottom row on floor row 2 (desk_pc, tv, bookshelf, fridge, kitchen
  pieces, lab_console, lab_shelf, terminal, heal_machine, mart_shelf).
- `wall_face` — decoration on the two wall-face rows (rows 0–1), `detail`
  layer over the wall tiles: wall_emblem_center / wall_emblem_mart (2×1, row 0),
  window(+_teal/_violet/_blue/_green), whiteboard,
  poster (1×2), clock (1×1, row 0), door_inner (1×2). stairs_up also uses rows
  0–1 but on the **ground** layer, replacing the wall tiles there.
- `floor` — anywhere on the floor.

## Counters (autotiles `counter_heal`, `counter_shop`)

A counter row at floor row `y`: base pieces `l, m…m, r` (or `s` alone) on
`detail` at row `y` — these are `solid` + `counter` (A-press talks to the NPC
behind). The matching `*_top` pieces go on **`over`** at row `y-1`: they draw
the counter top over the feet of the clerk/nurse standing there. For the
Token Mart use `m_top_register` on one middle cell for the cash register.
Model Center layout: `heal_machine` on the wall at rows 1–2, nurse at row 3,
counter base at row 4 (tops on row 3).

## Rugs (autotiles `rug_red`, `rug_blue`, `rug_teal`, `rug_violet`)

9-piece: corners `nw ne sw se`, edges `n s w e`, centre `c`; any size ≥ 2×2,
`detail` layer, walkable.

## Animated tiles

lab_rack (LEDs), lab_console (screen), heal_machine (core pulse), pc_storage
(screen) use the
standard Tiled `animation` arrays in `interior.tsj`.

## Id stability

Tile ids are append-only: new art is added after the last row, so existing
ids and catalog names never move (round 3 added bed_wide*, sofa, the wall
emblems and pc_storage from row 20 on).
