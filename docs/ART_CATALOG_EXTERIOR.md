# Exterior tileset catalog (ART-EXT)

Generated by `python3 tools/art/tiles_exterior/build.py` (one command rebuilds the PNG, TSJ, catalog, this file and the previews). Files:

- `public/assets/game/tilesets/exterior.png` - 16x16 tiles, 16 columns, no margin/spacing.
- `public/assets/game/tilesets/exterior.tsj` - Tiled tileset: per-tile properties (`solid`, `grass`, `ledge`, `water`, `door`) and `animation` arrays (kiosk screen 2x600 ms, water 4x280 ms, flowers 2x600 ms, tall grass 2x650 ms, fountain 3x220 ms, signal-tower beacon 700/500 ms).
- `public/assets/game/tilesets/exterior.catalog.json` - the names below -> tile ids (0-based, i.e. Tiled gid minus firstgid). `-1` = leave the cell empty.
- Previews: `tools/art/tiles_exterior/preview/` (`tileset_4x.png`, `scene_3x.png`, `scene_frame_4x.png`). `preview.py` contains a small reference implementation of every placement rule below (`Map.area`, `Map.forest`, `Map.fence`, `Map.stamp`) - copy it.

Art sources: ground, path/sand/water edge sets, ledges, tall grass, flowers and fences are hand-placed pixels in code (`ground.py`, `props.py`). Buildings, the tree, bush, rocks, signs, mailbox, lamp and bench are generated source images (`gen_sources.py`, cached in `tools/art/gen/raw/ext_*.png`), pixelized and snapped to `tools/art/palette.py` (red key-fringe pixels on the silhouette are re-inked with the warm outline: `genart._defringe`), then hand-corrected in `buildings.py` / `nature.py`.

## Layers

| map layer | what goes there |
| --- | --- |
| `ground` | grass variants, flowers, tall grass, path / sand / water autotiles, ledges, steps (all opaque) |
| `detail` | stamp `base` layers (buildings, trees, props), forest pieces, fences, bush, rock, sign, mailbox (transparent backgrounds) |
| `detail2` | anything that must sit on top of a detail tile (rare) |
| `over` | stamp `over` layers: roof tops, tree crown tops, lamp heads, town-sign board. Drawn above characters so the player walks behind them. Never solid. |

Stamps: copy `layers.base` into `detail` and `layers.over` into `over` at the same origin (top-left). Skip `-1` cells. Solid / door properties are already on the tiles.

Buildings: every `base` cell is `solid` except the door cell(s) on the bottom row, which carry `door: true` (walkable; put the `warp` object there). The path should run along the row directly below the stamp (the door step is drawn inside the stamp). Roof rows above the footprint are `over` and walkable, so the player can pass behind a building. Leave one free row between a building's over rows and anything solid above it if you want that walk-behind lane.

## Autotiles (`autotiles`)

### path, sand, water - 47-piece blob sets

Paint a set of cells as the material. Each material cell keeps a ~3 px grass margin where it borders grass, so the edge (and the rounded corners) are drawn INSIDE the material cells; plain grass cells around it stay plain `grass_*`. All on the `ground` layer. Water tiles are `water: true, solid: true` and animated; path and sand are walkable.

Named pieces (name = side where the GRASS is): `c`, `n`, `s`, `e`, `w`, outer corners `nw`, `ne`, `sw`, `se`, inner (concave) corners `inner_nw`, `inner_ne`, `inner_sw`, `inner_se` (material on all four sides, grass only in that diagonal). Example: the top-left cell of a rectangle of path is `nw`; the cell of an L-shaped path where grass pokes in at its NE diagonal is `inner_ne`.

`blob` covers every case including 1-tile-wide strips, ends and T-junctions. Key = 8 chars, one per neighbour in the order `n ne e se s sw w nw`, `1` = same material. Diagonals count only when both adjacent orthogonals are material (otherwise write `0`). Treat cells beyond the map edge as material. Pseudocode:

```
nb = {d: is_material(x+dx, y+dy) for d in n,ne,e,se,s,sw,w,nw}
for d,(a,b) in {ne:(n,e), se:(s,e), sw:(s,w), nw:(n,w)}: if not (nb[a] and nb[b]): nb[d]=0
key = ''.join('1' if nb[d] else '0' for d in [n,ne,e,se,s,sw,w,nw])
tile = catalog.autotiles.path.blob[key]
```

Water also has `c_variants`: three interchangeable all-water centre tiles with different ripple layouts. Whenever the blob key is `11111111`, pick one by a position hash so big ponds do not tile visibly. Dress ponds with `lilypad` (detail layer over water) and `reeds` (solid).

`pavement` (city paving, light stone slabs with a kerb against grass) has the same 13 pieces + `blob`, plus `c_variants` = [plain, cracked, manhole, drain]. Use plain for most centre cells, the cracked one occasionally (position hash), and place manhole/drain by hand. Combine with `plaza_inlay`, `crosswalk`, `bollard`, `kiosk`, `billboard`, `streetlight_modern`, `bike_rack` and the `hedge` autotile for city blocks. There are no road/car tiles by design.

Path, sand and water each have their own grass margin, so they do not butt against each other; separate two materials by at least one grass cell (a pond inside a beach is not supported).

### forest - walls of trees

Trees sit on a lattice of anchors `(ax, ay)`; a tree covers columns `ax..ax+1` and rows `ay..ay+2` (top, mid, bottom). Rows of trees stack every 2 rows so each crown overlaps the trunks behind it; columns sit every 2 tiles. For a rectangle: anchors at x = x0, x0+2, ... and y = y0, y0+2, ...; the block is `2*cols` wide and `2*rows+1` tall. Anchors may sit outside the map (e.g. ay = -1) to crop the wall at the edge. Per anchor, for each of its 3 rows:

- row kind: `top`; becomes `join` if there is a tree at `(ax, ay-2)`; `mid`; `bottom` (skip the bottom row if there is a tree at `(ax, ay+2)` - its `join` row covers it).
- left cell: `l_in` if a tree at `(ax-2, ay)` else `l_out`; right cell: `r_in` if a tree at `(ax+2, ay)` else `r_out`.
- tile = `forest[<row kind>_<col kind>]`, on the `detail` layer. All forest tiles are solid. Gaps between crowns inside the wall are filled with deep foliage; the outer silhouette stays open and shows the ground layer.

See `Map.forest` in `preview.py`. Single trees in the open use the `tree` stamp instead.

### fence_wood, fence_white, hedge

Paint fence/hedge cells (detail layer, all solid; `hedge` is a clipped box hedge for neat city borders and uses the same keys). `byConnection[conn]` where `conn` lists the neighbouring fence cells in the order `n e s w` (e.g. `"ew"` horizontal run, `"ns"` vertical, `"es"` top-left corner, `""` lone post). Friendly aliases: `h`, `v`, `end_w`, `end_e`, `end_n`, `end_s`, `corner_nw`, `corner_ne`, `corner_sw`, `corner_se`, `t_n`, `t_s`, `t_e`, `t_w`, `cross`, `post`.

## Ledges in practice

A down-ledge line on Route 101: `ledge_s_end_w, ledge_s x N, ledge_s_end_e`. To leave a gap you can walk up, put `steps` between an `ledge_s_end_e` and an `ledge_s_end_w`. For a raised plateau: left side `ledge_w_end_n` then `ledge_w` x N, bottom-left `ledge_corner_sw`, bottom `ledge_s` x N, bottom-right `ledge_corner_se`, right side `ledge_e` x N topped by `ledge_e_end_n`. Ledges are ground tiles (grass baked in); the plateau top and the lower ground are ordinary grass.

## Tile id stability

New art is only ever appended after the last existing row (see the "Round 3" block at the end of `build()`), so existing tile ids never move. Keep it that way: add new sections at the end.

## Known limits

- Path/sand/water must be separated by a grass cell (each has its own grass margin).
- Ledge inner (concave) corners are not provided; build plateaus as convex shapes.
- Forest pieces assume walls built from whole trees on the 2x2 lattice (rectangles and L/U shapes made of rectangles work).
- Building art is pixelized from generated images, so outlines are slightly less regular than the hand-placed ground tiles.
